# Validation of the pure-2D implementation

The pure-2D implementation is checked at three independent levels: operator
properties, coefficient recovery from exactly constructed discrete trajectories,
and a cross-code comparison against the CUDA PSANC2D solver.  The last comparison
is intentionally external to the simulation code: ActiveBE Validator reconstructs
the equation terms from saved PSANC2D fields rather than reusing PSANC2D kernels.

## Model conventions

The pure-2D order parameter is a symmetric traceless 2 x 2 tensor,

```text
Q = [[ Qxx, Qxy],
     [ Qxy,-Qxx]].
```

Consequently `Tr(Q^3) = 0` identically and the two-dimensional bulk model has no
independent cubic-invariant (`a3`) term.  The independent components used by the
regression routines are `Qxx` and `Qxy`.

PSANC2D writes its flow couplings using three independent coefficients
`lambda1`, `lambda3`, and `lambdaR`.  ActiveBE Validator represents the same
structures as `e_plain`, `q_colon_e_q`, and `omega_q`.  The rotation convention
must be converted explicitly: the PSANC2D term corresponds to
`-lambdaR * (Omega Q - Q Omega)` in the Validator convention.

## Analytic/discrete regression tests

`tests/test_two_d_numerics.py` contains deterministic periodic-field tests.  They
check that the spectral Q-equation basis preserves symmetry and tracelessness and
that both pointwise and local weak-form regression recover known coefficients from
trajectories generated by the same discrete operators.

The Q regression exercises the independent basis

```text
u.grad(Q), Omega Q - Q Omega, D, Q(Q:D), Q, Tr(Q^2)Q, laplacian(Q).
```

The velocity regression independently exercises

```text
u, u.grad(u), laplacian(u), div(Q).
```

Both the pointwise and local weak-form coefficient-recovery tests pass at tight
floating-point tolerances.

## PSANC2D GPU cross-check

A deterministic non-square `12 x 14` periodic case was run with the actual
PSANC2D GPU executable on the Brandeis HPCC.  The case uses multiple Fourier
modes and non-default values of the bulk, elastic, active, friction, and all three
flow-coupling parameters.  Saved `Q^0`, `Q^1`, and `u^0` fields were then analyzed
independently by ActiveBE Validator.

For the Stokes solve, an independent Fourier-space reconstruction gave

```text
max |u_PSANC - u_independent| = 3.7947076036992655e-18
RMS |u_PSANC - u_independent| = 1.1589908087891114e-18
```

Using Validator's `div(Q)` and `laplacian(u)` operators, the transverse-projected
Stokes balance

```text
P[alpha div(Q) + eta laplacian(u) - friction u] = 0
```

had residual

```text
max absolute residual = 3.980048042180789e-17
RMS residual          = 9.22089540859685e-18
```

For the Q equation, the Validator basis fields were assembled using PSANC2D's
actual semi-implicit time discretization.  The reconstructed first step agreed
with the GPU result to

```text
max |Q1_validator - Q1_PSANC| = 5.551115123125783e-17
RMS difference                = 1.3468090951147876e-17
relative max difference       = 4.633272116895304e-16
```

These errors are at double-precision roundoff scale.  This checks not only the
individual spatial operators but also their signs, tensor conventions, parameter
mapping, Stokes projection, and PSANC2D semi-implicit Q update.

## Reproducing the checks

The self-contained regression suite is run by `pytest`.  The external PSANC2D
comparison is retained as `dev/crosscheck_psanc2d.py`; it expects the small raw
cross-check output as an argument and is not part of CI because it depends on an
external GPU solver and HPCC-generated data.

CI therefore verifies the portable analytic/discrete tests on every supported
Python version, while the PSANC2D comparison serves as an independent solver-level
reference check when the external data are available.
